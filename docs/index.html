A performance layer for Filament v5

Filament, without the roundtrip.

Filament renders its tables through Livewire — every sort, page, search and filter is a full server cycle that re-renders the whole component and morphs the DOM. Villament swaps that table for a Vue island fed by your resource's own table() schema, so interactions ride a lean JSON call instead. Same resource, same markup, a fraction of the cost.

class ListCourses extends VillamentListRecords { }
// one-line swap — was ListRecords
The idea

Move the fast path off the server.

A Livewire table treats a click as a request. That's the right default for forms and stateful flows — and the wrong one for a grid you sort, page and search dozens of times a minute. Villament keeps the first paint exactly as Filament renders it, then takes over the hot path.

Livewire
click→ server re-render→ full HTML→ DOM morph
Villament
click→ JSON endpoint→ rows only→ Vue patch

Principles

Filament stays in charge.

The whole point is to be invisible. If a rule ever forces you to redefine what Filament already knows, the rule is wrong. Six invariants hold the line.

SOURCE OF TRUTH

One definition, not two.

Columns, filters, scoping and authorization all come from your existing table() and getEloquentQuery(). Villament reads them; it never asks you to restate them.

NO CLOSURES

Logic stays on the server.

Every closure — formatting, colors, visibility, URLs — is evaluated server-side and shipped as a flat, pre-rendered cell payload. Vue renders values, never your business rules.

WHITELIST

Nothing trusted from the client.

Sort, search, filters, page, per-page and cursor are each validated against the real schema. An unknown or malformed parameter is rejected, not applied.

PANEL-NATIVE

Your security, unchanged.

The endpoint runs inside the panel's own middleware and gates on canViewAny(). It's tenancy-aware, so multi-tenant records stay isolated and record URLs resolve per tenant.

BYTE-FIDELITY

Indistinguishable from stock.

The island reuses Filament's exact fi-* markup and server-rendered icons, with near-zero custom CSS. Same look, same dark mode, same RTL — down to the class names.

DELEGATE

Reimplement nothing complex.

High-frequency interactions go Vue/AJAX. The filters panel, actions and modals stay native Livewire, joined by a thin bridge — so filter types you've never heard of just work.

How it's built

An island, and a bridge back to Livewire.

Vue owns the grid inside a wire:ignore mount. Where an interaction needs Filament's server state, a bridge speaks Livewire's own protocol instead of forking it.

harness

HeadlessTableHarness

Boots the real List page, applies the validated request state, and reads records through Filament's own query pipeline — no parallel query logic.

serializers

Schema + Record

The schema is serialized once; each response carries only per-record cells, meta and indicators. A version hash detects drift and hard-reloads on deploy.

endpoint

Lean JSON route

Tenancy-aware, canViewAny-gated, optional HTTP caching. It returns data, not markup.

bridge

Livewire commit hook

Mounts actions via Filament's unified mountAction and syncs filter state through the request's respond() lifecycle — so the island stays in step even when the component itself never re-renders.

In your code

The only diff is the parent class.

Villament reads the resource you already wrote. Your table() stays exactly as it is — the change is the List page's base class, and the import that comes with it.

✓ Unchanged · CoursesTable::configure()
// You already have this — Villament reads it verbatim.
public static function configure(Table $table): Table
{
    return $table
        ->columns([
            TextColumn::make('title')->searchable()->sortable(),
            TextColumn::make('level')->badge(),
            IconColumn::make('is_published')->boolean(),
        ])
        ->filters([
            SelectFilter::make('level')->options(CourseLevel::class),
        ])
        ->recordActions([EditAction::make()]);
}

No new column definitions, no duplicated filters, no client-side query, no header actions to move. If it renders in Filament, it renders in Villament — the island just serves it over JSON.

Install

Four steps to a faster panel.

A standard Composer package with a Filament plugin. Nothing to configure to get started — the config file is there only when you want to tune it.

Require the package

Pull it in with Composer. It targets Filament v5, Laravel 12/13 and Livewire 4.

$ composer require zvizvi/villament

Register the plugin

Add it to your panel provider. This wires up the JSON data route inside the panel's own middleware and tenancy.

return $panel
    ->plugins([
        VillamentPlugin::make(),
    ]);

Publish the assets

Ship the island bundle to public/. It's content-hashed, so a rebuilt bundle busts the browser cache on its own.

$ php artisan filament:assets

Swap the List pagethe one line

Extend VillamentListRecords instead of ListRecords. Header actions, widgets, tabs and breadcrumbs keep working untouched.

class ListCourses extends VillamentListRecords { /* … */ }

Tune it, if you likeoptional

Publish the config to adjust the search debounce, HTTP cache TTL, or register custom cell/column serializers for bespoke column types.

$ php artisan vendor:publish --tag=villament-config
